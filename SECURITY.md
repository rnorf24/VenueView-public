# Security Policy

Please do not include real calendars, event titles, organization configuration,
personal information, credentials, or private output when reporting a problem.
Use a minimal synthetic example instead.

For a security concern, open a private security advisory on the repository if
that feature is enabled. Do not post exploit details or confidential data in a
public issue. Maintainers should acknowledge a complete report, reproduce it
with synthetic data, and publish remediation details only after a fix is ready.

The current public candidate receives security fixes on its latest release
candidate line. It is a local single-user utility and is not designed for
internet exposure or multi-user hosting. See [`docs/SECURITY.md`](docs/SECURITY.md)
for its threat boundary and [`docs/PRIVACY.md`](docs/PRIVACY.md) for data rules.
